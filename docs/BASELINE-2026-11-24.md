# Baseline - one real session, 24.11.2026

A single agent session in a product repository, measured from the OpenCode
database after the fact. It is the "before" for a change to rule 13 and to the
`review-team` budget: the session spent most of its wall time re-running slow
checks, not writing code.

The full command list of that session is **not published** - it names the
project, its hosts and the user's paths. The numbers below are the aggregate
table and the category split; the database still holds every call.

## Method

- Data: `opencode.db`, table `session_part`, the rows of `type='tool'`.
- Duration of a call: `time_updated - time_created`, milliseconds.
- `active` span: first call's `time_created` to last call's `time_updated` -
  "first step to last step". Tool calls overlap when parallel, so the sum of
  durations can approach the span without partitioning it.
- Read-only URI (`mode=ro`): the measurement never writes to the database.

Reproduce with the tool in this repository:

```sh
python tools/session-time.py --session <id> --slow 60
python tools/session-time.py --session <id> --match mutate --match acceptance
```

The session was measured again later the same day: 300 shell calls and a
138.1 min span against the 293 calls and 134.2 min below, because the session
continued after this table was written. Both readings come from the same
`session-time.py` rule; the difference is 7 later calls.

## What the targets are

| Target | Baseline | Goal |
|---|---|---|
| Shell share of the active span | 85.7% | 70% or less |
| Full mutation suite | 2 | 1 or fewer |
| Acceptance suite | 5 | 2 or fewer |
| Numbers check | 12 | 2 or fewer |
| Database shell (container) | 27 calls, 522.7 s | 5 calls or fewer |

The hypothesis under test: the heavy loop ran twice because it ran before the
review, and each reviewer re-ran the full suite for itself. If the text change
does not move these numbers, the conclusion is that text is not the lever and
the tools need flags (`--changed` for the mutation suite, `--only` for the
numbers check), not another sentence.

Measured 24.11.2026: the review-order hypothesis is refuted. Both full mutation
runs started before the review fleet did, and the second followed an edit to the
mutation tool itself, not a review finding. A text change aimed at re-running a
long check for another slice of its output was tested on a synthetic task and
refused - see `EXPERIMENT-2026-11-24.md`.
